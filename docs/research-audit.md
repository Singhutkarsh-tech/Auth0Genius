## Quality guardrails

- Claim references must point to saved sources. “Verified” claims require an official source; third-party pages are labeled.
- Durations are engineering estimates with assumptions, not provider promises. External waiting time is unknown unless established.
- Live source IDs and links are supplied by the server, never accepted as invented LLM citations.
- Structural validation cannot prove a source semantically supports every sentence. The UI discloses this limit, and human review remains important.
- Search and fetched pages are treated as untrusted data. No scripts or document instructions are executed.

Live-run and automated validation results are recorded separately in [validation.md](validation.md).

### Zerodha guide correction and fresh research — 26 October 2026

The saved Zerodha guide previously missed Kite's developer documentation and therefore showed OAuth and its mechanism as unverified. The retrieval profile now recognizes `kite.trade` as Zerodha/Kite Connect's official developer domain and fetches the official user login, agent setup, and API overview pages directly, while still validating fetched text before it becomes evidence. A fresh live run for **Zerodha** used Tavily search, fetched those official Kite docs and Composio docs, synthesized the guide with OpenAI, passed source/schema validation, and saved it in an isolated local database. This was a real provider research run, not a fixture.

The resulting guide classifies the flow as **OAuth-like proprietary** and OAuth-style support as documented; it does not label it standard OAuth 2.0. The checklist describes developer app/redirect setup, receiving `request_token`, server-side checksum exchange using `api_secret`, and safe API-session testing. Each concrete step points to retained official Kite documentation. It explicitly warns that Composio compatibility with this provider-specific exchange is unverified. Managed auth and provider approval remain unknown. Trading compliance appears as a separate use-case-conditional note, not an OAuth app approval requirement. No Zerodha login, account setup, API secret, or connected-account test was performed. Run stages, citations, and the remaining unknowns are in [live-research-zerodha-local.json](live-research-zerodha-local.json).
